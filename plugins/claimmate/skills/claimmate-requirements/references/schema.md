# 报销要求工作簿

`报销要求.xlsx` 是 ClaimMate 唯一面向业务的要求 Schema。普通用户只维护这个工作簿，不需要编辑 JSON。

## 用户只维护三列

每行代表一个费用类型：

- `费用类型`: 例如机票、高铁票、出租车票。
- `必须材料`: 多项用 `、` 分隔；同一项存在替代材料时用 `或`，例如 `火车票或电子发票、付款记录`。
- `财务其他要求`: 没有就留空；条件要求可以写成 `网约车还需行程单`。

机器使用的费用类型 ID、别名、大类、规则编号和阻断标记由 ClaimMate 在内部生成，普通用户不维护。大模型识别费用、材料、配对和特殊条件是否成立；确定性代码只验证模型输出、合计付款金额，并按内部规则核验材料是否齐全。

## 首次配置如何确认

1. 初始化目录并记录使用者姓名和是否接入邮箱；此时不处理材料，也不启动监听器。
2. ClaimMate 把本工作簿的全部三列内容展示给用户。
3. 用户需要修改时，ClaimMate 先展示单项修改前后内容，确认后写入；用户也可以直接编辑工作簿。
4. ClaimMate 再次展示完整 Scheme。只有用户明确确认整份内容后，才记录工作簿哈希、开始处理材料并显示正常用户引导。
5. 用户以后直接修改工作簿导致哈希变化时，自动处理暂停，直至新内容再次展示并确认。

## 财务反馈如何改变要求

1. 大模型从财务原文或附件中提取费用类型、必须材料和财务其他要求。
2. 用户选择“以后都适用”或“只针对这次出差”。
3. ClaimMate 显示修改前后内容，等待用户明确确认。
4. “以后都适用”会先备份再更新本工作簿，并重新验证；“只针对这次”保存为项目临时要求，不修改本工作簿。
5. 原文、附件、适用范围、确认时间和变更内容保存在隐藏审计目录。

因此全局要求仍以本工作簿为唯一用户可见 Scheme；项目临时要求只在对应项目的状态与交付审查中显示。
